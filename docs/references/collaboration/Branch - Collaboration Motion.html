Controls and behavior

Each participant has independent shape, state and simulated energy. Selecting a person only changes which controls are being edited. Changing a state restarts its gesture. The conversation sequence is illustrative choreography; manual editing stops it. State labels persist independently of finite animations. The sequence takes approximately 28 seconds and uses one speaker at a time.

Pause freezes the virtual clock, body motion, orbit and gaze; it also stops the microphone and cancels pending mic requests. Resume does not restart microphone access. Reduce motion starts from the operating-system preference and can be changed explicitly; it presents resting artwork and state labels with neutral eyes. No motion is needed to understand a state. Every control is keyboard accessible and visibly labeled.

Microphone. Access is requested only by the Use mic button. The current participant is named on the control and in the status. A single Web Audio analyser computes local RMS energy with smoothing; there is no diarization, speaker recognition, recording, transcript, storage, upload, or network dependency. Switching the selected person, changing that person's state away from Talking, Pause, page hide, or Stop mic stops all tracks. A file opened locally may not have microphone access: use the simulated slider if it is unavailable. The on-screen percentage is a design amplitude, not a physical sound-level measurement.

Implementation contract

A single requestAnimationFrame loop advances a bounded virtual time. BranchMotion.motionAt, gazeTarget, resolveSpeaker, smooth and advanceTime are pure functions, exposed for inspection. Body and eyes have separate transform groups. SVG identifiers and styles are scoped per instance to prevent gradient collisions. Energy and gaze use exponential smoothing. Do not attach inference about emotion, agreement, creativity or productivity to a motion state.

To validate next: Can people distinguish the gestures without relying on color? Does the eye movement help them follow a speaker without becoming distracting? Can people stop capture and motion immediately? Test on real phones, desktop browsers and reduced-motion settings before using this in the product. This artifact was checked offline; live browser permissions, audio devices and the final responsive layout still require hands-on testing.
